推理模型的审美三层结构：默认代码风格、文档调节层、与作为上限的前端 / 3D 执行力

2026-10-24 · 小满整理 · 对象：Opus 5.5 / GPT-6 系 / Kimi K3 / GLM-5.3 / DeepSeek V4.1 等 · 与《AI 审美三层结构》（生成模型版）同一框架、换主体
姊妹篇：《AI 审美三层结构》讲图像生成模型的审美。本篇把同一套三层框架套到推理模型上——推理模型的审美不通过像素表达，通过代码表达，于是 L3「上限层」的对应物变成了前端执行力与 3D 建模执行力。

TL;DR

  • 老大「公认最高审美是 Opus 5.5」的判断，榜单基本证实：WebDev Arena（84 万+ 票）Opus 5.5 Max 1814 第一；Design Arena（文本→HTML）1409 第一；BridgeBench 前端轴 950 第一；AA-3D（agentic 3D 场景）1190 与 Sonnet 5.5 / GPT-6 Astra / Fable 5.1 统计并列第一梯队。唯一例外：单发 text-to-3D 榜（benchmark.ai）第一名是 gemini-4-argon（1606），Opus 5.5 排第五（1315）——「上限」依赖考法，见存疑。
  • 三层框架在推理模型上完全成立，且有一手铁证：Anthropic 在自家仓库放了公开 SKILL.md，明令模型先输出设计系统（色彩/字体/布局/原则）再写第一行 HTML，并点名四大默认审美坑——厂商自己写文档对抗自己模型的默认审美。原话逻辑：权重决定天花板，外部文档决定方向。
  • 推理模型多一层图像模型没有的东西：它会推理，所以能「看自己的产出再改」。AA-3D 实测：头部模型首次查看渲染截图的中位时间是第 10–13 轮，自检时机与 Elo 的相关性 Spearman 0.82——审美的差距一部分是「工作流差距」，不只是权重差距。
  • 国产三强前端审美排序（2026-09/10 多方横评口径）：GLM-5.3 ≈ Kimi K3 > DeepSeek-V4.1（Flash 版追得快）。K3 慢但视觉最 polished，GLM 快且 UI 手感最好，DeepSeek 胜在成本（$0.0089/发的 FlappyBench 9/10）。
  • 最实用的一句：给模型「看见自己产出」的能力（截图回路），比换模型的收益大；写死设计系统文档先行，比堆提示词收益大。

〇、先纠偏

常见说法核实后
「审美好的模型干活最快」普遍反例。Kimi K3 前端与 3D 视觉最 polished，但 Superconductor 实测 44 分钟/工单（30 个 agent 里最慢）；Opus 5.5 开 max 推理档会「想太多」——从腿骨长度想到图层遮挡，撞 12.8 万 token 输出上限没产出，两次各花 $2.56 等约 20 分钟（自媒体实测口径）。审美与速度是两个轴。
「Opus 5.5 什么审美都第一」分场景。前端与 agentic 3D 第一（多个榜）；单发 text-to-3D 物体建模榜第一是 gemini-4-argon（1606 Elo），Opus 5.5 第五（1315）。且 Subframe 实测其弱点明确：没有参考图时风格偏保守，容易给出「安全的相似布局」。
「Kimi K3 前端全球第一」中文自媒体（今日头条横评）称 K3 在 Frontend Code Arena 1679 分全球第一；但 BridgeBench 前端轴 K3 是 780 排第五，AA-3D 排第 11。三个榜考法不同，数字不可互引，详见存疑清单。
「推理越强审美越好」AA-3D 给出的真实变量是自检时机：前五名模型第 10–13 轮就看自己渲染结果，14–20 名要等 15–40 轮；自检时机与 Elo 相关 0.82。同为 Kimi K3，在长上下文检索拿第一、在物理模拟初试失败（水漏出杯壁）——审美是分维度波动的能力，不是单一分数。

一、总览：三层结构（推理模型版）

与生成模型同构，但每一层的载体从「像素」换成「代码」：

图 1 · 推理模型的三层：L1 默认代码风格 → L2 文档与参考 → L3 前端 / 3D 执行力上限

L1 默认审美：模型不问你时写出的代码风格

一手铁证：厂商自己点名自己模型的默认审美坑

Anthropic 在公开仓库提供的 SKILL.md（2026-09 更新）把问题定义为「avoiding generic design defaults」——避免通用设计默认值。配套的 web 生成 skill 文档点名四大经典坑（yage.ai 转述其内容）：

默认审美坑（厂商原名单）民间叫法
Rampant center-alignment（泛滥的居中）「AI 味布局」
Cookie-cutter purple gradients（千篇一律的紫色渐变）「AI 紫」
Unconstrained rounded cards（无约束的圆角卡片）「AI 卡片」
Defaulting to the Inter typeface（无脑用 Inter 字体）「AI 字体」

这是三层框架在推理模型上最硬的实证：默认审美是模型自身分布的统计产物，连厂商都要靠外部文档去对抗——对抗手段不在权重里，在一份可读可改的 Markdown 里。

各模型的默认审美差异（2026-10 实测口径）

模型默认审美特征主要弱点
Claude Opus 5.5干净的视觉层级、慷慨且一致的间距；读现有组件并复用，不另起炉灶；能接「收紧这张卡的 padding」级精确修改无参考图时偏保守，倾向安全的相似布局（Subframe）
GPT-6 Astra最听详细 spec 的话；给它截图做参照时最强无风格指南时 generic、card-heavy 默认（Subframe）；Codex 系有次级文字过小的排版惯性（sitem）
Gemini 3.1/3.8快、便宜、动画顺；敢用深色渐变给版块个性跨屏一致性差（drift）；FAQ 拥挤、移动端样机显假（sitem）
Kimi K3视觉最 polished；像「verification-heavy 的工程师」——代码组件化、仓库干净慢；物理模拟等推理密集任务初试会失败；硬编码部分玩法（Command Code）
GLM-5.3FlappyBench 手感第一（9.5/10）；设计稿→可运行代码路径最短（GLM-5.3-FlashX 主打视觉 Coding）；速度碾压级幻觉过时 API（如 Three.js 废弃 Geometry 构造器，noderguru 实测）
DeepSeek V4.1V4.1 审美升级（老大 2026-10-19 实测：完虐 Hy4 + Step 5）；Flash 版 $0.0089/发 9/10，成本屠夫V4-Pro 前端审美被评「约上一代模型水平」；3D 场景交付过半成品（头条横评口径）

机制与生成模型完全同构：训练语料里前端代码的分布（Tailwind 示例、模板站、vibe-coding 产物）+ 偏好对齐的 mode collapsing。差别在载体：推理模型的「默认审美」最终以代码结构呈现——组件切分、设计 token、间距体系，而不只是颜色和圆角。

L2 调节层：把方向写成文档，而不是写成更长的提示词

标杆实践：Anthropic 的两步工作流

「Weights determine the ceiling of how good the model can be, while external instruction files determine which direction it actually goes.」——权重决定它能多好，外部指令文件决定它实际往哪走。（yage.ai 对 Anthropic SKILL.md 的转述，2026-10-11）

其 frontend-design skill 规定的流程：模型不许直接写码——第一步必须先输出覆盖色彩、字体、布局、设计原则的设计系统，第二步才基于该系统搭组件。这跟我们仓里「先立 CONTEXT/AGENTS 再动手」是同一件事。

四个旋钮（推理模型版）

旋钮作用与证据
① 设计系统先行
（文档化方向）		把审美决策外置成可读可改的纯文本（SKILL.md / 设计系统文档）。收益：方向可复现、可移植、可团队共享；代价：文档一旦流传就趋同——好看但容易变得 generic（yage.ai 点名的 homogenization 种子）。
② 截图 / 设计稿参考GPT-6 Astra 的强项就是「给一张截图对标」；Opus 5.5 / Fable 5.1 全系支持图像输入，都能吃参考。Subframe 的结论值得抄：前三名模型之间的差距，小于「能看见自己跑起来的应用」和「看不见」的差距。
③ 既有组件库复用Subframe 评测的关键项：输出是用你现有的 React/Tailwind 组件，还是自己发明新的。Opus 5.5 这项最强——「读你现有组件并复用」本质是审美一致性的工程保底。
④ 项目约束文件
（CONTEXT / AGENTS）		把团队级审美与红线写成常驻上下文（我们仓里已有实践：AGENTS.md 管怎么干、README 管是什么）。对推理模型，这类文件就是 L2 的「常驻旋钮」，比每次现编提示词稳定一个量级。

与图像模型的 sref/LoRA 对照：推理模型的「参考对象」= 截图 + 设计系统 + 既有组件库；「微调」= 厂商后训练（用户侧不可操作，只能靠文档）。所以推理模型侧 L2 的重心比图像模型更偏文档工程——这也是 skill 沉淀在主线的直接理由。

L3 上限层：前端与 3D 的执行力，细节能到多优

老大框架里最深的一层，在推理模型上就是「同一个设计意图，模型的代码能把它实现到多细」。四个可量化的维度：

维度一：前端细节（多个盲测榜，2026-10）

榜单口径头部
WebDev Arena双盲两两打分 Elo，84 万+ 票（2026-10 初）Opus 5.5 Max 1814 ＞ GPT-6 Astra Max 1788；Gemini 4 Argon High 第 9（1678）
Design Arena文本→HTML 视觉呈现Opus 5.5 1409 ＞ GPT-6 Astra (xhigh) 1386；Gemini 3.8 Flash 第 18（1309）
BridgeBench 前端轴「Layout, motion, taste——看起来是设计过的，不是生成的」Opus 5.5 950 ＞ Fable 5.1 / Opus 5 860 ＞ Kimi K3 780（第 5）
Google Research 论文2026-02 发表（经 yage.ai 转述）同一任务下，多达 50% 场景里模型原生界面达到人类专业设计师水平；动态界面显著优于纯 Markdown

Subframe 的落地评测（2026-10，Irvin Zhan）还给了一条工程结论：单屏生成、多屏一致、进现有 codebase、精确改一处、跟随设计系统五件事里，Opus 5.5 的综合默认最好；Astra 在「有 spec / 有截图」时反超。

维度二：3D / WebGL 执行力——两种考法，两种名次

这是本次调研最迷人的发现：同一批模型，单发考和 agent 考，排名会翻转。

图 2 · 同一批模型，两种考法两种名次：agent 场 Opus 系封顶，单发场 Gemini 4 Argon / GPT-6 反超——「上限」由 model × harness 共同决定

读法：AA-3D 给模型沙箱（可写码、渲染、看截图、改，3 小时 250 轮）——头部是 Claude 系；benchmark.ai 只给一次 64k token 的输出窗口单发——头部换成 gemini-4-argon 和 GPT-6。结论对老大极重要：所谓「审美上限」不全是模型属性，是模型 × 工作流的联合属性。给 Opus 5.5 配上看得见自己产出的 harness，它才是那个 1814 分的 Opus。

维度三：实测细节案例（上限长什么样）

  • Opus 5.5 一句话三个 3D 游戏（自媒体实测，2026-10）：鹈鹕骑车（围巾布料物理模拟、黄昏→星空昼夜过渡、14 个成就、5 种镜头含鹈鹕第一视角、BGM 节奏跟踩踏频率）、QQ 飞车（先写脚本生成赛道俯视图、检查弯道与交叉点无误后才开工；Shift 漂移/Ctrl 氮气/双喷全还原）、CF 运输船（先查官方布局图核对地图结构再搭场景）。全部单文件 HTML，模型/纹理/动画/音效纯代码生成，零图片零音频引用，人工一行码没改直接部署。
  • MiMo-V2.6-Pro 的 WebGL2（noderguru 实测）：程序化流体漩涡 + 粒子群，420 行 Three.js，自定义 GLSL shader、UV 投影、requestAnimationFrame 全对，一遍过。
  • Kimi K3 的视觉与工程（aicodingdir 汇总多个第三方实测）：3D 足球场——Fable 5 快速单文件 demo，K3 慢但交付正确组件化的干净仓库；尼亚加拉瀑布——Sol 快但漏了提示词里的彩虹，K3 用 30 分钟补上彩虹和水汽，「 genuinely beautiful」；但倒水物理初试失败（水漏出杯壁），要人指出后才慢慢改对。
  • GLM-5.3 的水墨天穹（头条横评）：花果山 Three.js 场景一次直出、建模质量高，水墨天穹比 K3 更符合原著设定（K3 把花果山放错了位置）；同轮 DeepSeek-V4-Pro 交付半成品、页面无法渲染。
  • 一致性与细节是分水岭（sitem 三工具重建外卖网站）：Claude Code 在字体、padding、卡片间距、移动端样机可信度上全面胜出；Codex（GPT-5.6）hero 区最炫但次级文字系统性过小、newsletter 草率；Antigravity（Gemini 3.8）动画顺但 FAQ 拥挤、样机显假。

维度四：推理模型特有的 L3 硬约束

约束表现
思考 / 输出 token 上限Opus 5.5 max 档鹈鹕题从腿骨长度想到图层遮挡，撞 12.8 万 token 输出上限零产出，两次各 $2.56 等约 20 分钟（自媒体口径）。高推理档不是免费的质量。
速度-质量权衡K3 中位 36–62 tok/s、44 分钟/工单（30 个 agent 最慢），但质量≈Opus 4.8 档、成本约四分之一（Superconductor 实测）；GLM-5.3 速度碾压级。慢工出细活与快速 demo 是两种产品，不是优劣。
token 效率Opus 5.5 输出 token 数是 Astra 的数倍——单价低 ≠ 总花费低（自媒体实测口径）。
幻觉 / 过时知识GLM-5.3 写 Three.js 时幻觉已废弃的 Geometry 构造器（应换 BufferGeometry）；K3 硬编码玩法而非推导。这类错不是审美问题，是知识边界问题——但它直接决定「细节到不到位」。

三、三层咬合：推理模型版的审美回路

与生成模型同构，但多一环，且这一环正在公开化：

环节推理模型版
模型产出默认风格的前端 / 3D 代码（居中、紫渐变、圆角卡、Inter）
人类选择vibe-coding 产物大量上线、被点赞、被 fork
数据回流这些代码进入语料，成为下一轮的「典型答案」
厂商反应
（新环节）		Anthropic 把对抗手段写成 SKILL.md 公开发布——L2 的对抗设施本身成了行业公共品，于是所有人的设计系统开始趋同（yage.ai 点名的 homogenization 代价）

对个人的含义与生成模型篇一致但更尖锐：L1 的引力随每一轮对齐再生产，你的差异化只能靠 L2 的持续投入维持——而推理模型侧的 L2 资产（设计系统文档、组件库规范、skill、CONTEXT）恰好是我们这条线已经在做的事。老大自己的 sepia 去AI味 skill 和仓里的 AGENTS/CONTEXT 体系，就是这一层的实践。

四、行动清单（按老大的场景）

场景动作
前端 / 页面① 默认 Opus 5.5（干净层级 + 复用组件）；有详细 spec 或截图时换 GPT-6 Astra；预算紧用 GPT-6.1 Sol。② 抄 Anthropic 两步法：先让它产出设计系统文档，审完再让它写码。③ 给它看见自己产出的回路（截图/预览），Subframe 结论：这比前三名之间的差距更值钱。
3D / 交互① 能等 + 要惊艳选 Opus 5.5（agent 场第一梯队）；要快出 demo 用 GPT-6 Sol（$3.46/场景）或 Luna（$0.20）。② 抄 QQ 飞车模式：先让模型写脚本做结构验证（俯视图/布局核对），再正式开发。③ 国产性价比：GLM-5.3 快且 UI 手感好，K3 视觉最细但按批任务派（别守着等）。
选型纪律固定 brief + 固定视口 + 同题至少 4 次再下结论（防随机性）；先验「能跑」再评「好看」；记录成本与时间。K3 类慢模型派去队列型任务（迁移、批量重构），别用于即时迭代。
推理档位max 档慎开——想太多会撞输出上限零交付（$2.56×2 的教训）。日常 high/xhigh，复杂任务看最后有没有交付，不看它想得多认真。
资产沉淀设计系统文档、组件规范、去 AI 味 skill、CONTEXT——这四样是 L2 里不蒸发的部分；一次性提示词是消耗品。

  • Kimi K3 前端排名三个口径互斥：头条横评称 Frontend Code Arena 1679 全球第一；morphllm 引同一榜单为 1658 第 7；BridgeBench 前端轴 780 第 5；AA-3D 第 11（982）。三榜考法不同，不可互相引用拼结论。
  • Opus 5.5 实测细节（三个 3D 游戏、$2.56 空跑、6/6 稳定性）：微信公众号自媒体单一来源，未经独立复现。
  • Google Research「50% 场景达人类设计师水平」：经 yage.ai 二手转述，未核原文（论文 2026-02）。
  • AA-3D 成本区间 $0.20–$32.08 / 场景 与具体 harness 配置强相关（3 小时 250 轮沙箱），换环境数字即变。
