# 技能进化细则（evolution）

> 本文件是 [SKILL.md](../SKILL.md) 的细节层：判断一个工作流值不值得固化、固化到什么程度、何时合并或归档。

---

## 1. 证据模板（Observe）

复制到工作笔记或回报里，逐项填**真实发生的事实**：

```text
任务：
重复次数：
起点 / 输入：
实际步骤：
关键判断 / 分叉：
失败路径 / 坑：
用户纠正：
验证方式：
最终结果：
运行环境 / 工具版本：
```

判断标准：只写「下次还适用」的内容；本次特有的任务名、临时路径、一次性数据不进入技能。

---

## 2. 可复用性评分（启发式）

每项 0–2 分，总分 10：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 重复性 | 明显只做一次 | 可能再遇到 | 周期性 / 高频 |
| 稳定性 | 每次做法都不同 | 大方向稳定 | 步骤已跑通、结果可复现 |
| 特异性 | 边界模糊 | 有大致范围 | 触发和输入输出明确 |
| 收益 | 固化后不省事 | 略省时 | 明显省时 / 少犯错 |
| 可验证 | 无完成标准 | 有粗略检查 | 有命令 / 检查点 |

- **≥ 6 分** → 创建技能。
- **4–5 分** → 记候选，等下一次证据。
- **≤ 3 分** → 不固化，留在会话 / 笔记里。

分数只是辅助；用户明确要求时可直接创建。

## 3. Hermes 学习循环对照

| Hermes | 本技能 | 关键点 |
|---|---|---|
| Observe：记录多步任务、工具调用、分支、用户纠正 | §0 收集证据 | 只观察，不急着总结 |
| Distill：3+ 次成功后生成 `SKILL.md` | §1–§4 判断与落盘 | 先查重，再写 |
| Reuse：按需加载，description 只占少量 token | §5 注册与验证 | 主流程 + references 渐进披露 |
| Refine：使用中按反馈修补技能 | §6 进化已有技能 | 改技能，不只改这次输出 |
| 失败路径剪枝 | §6 | 删无效步骤，避免技能膨胀 |
| Memory vs Skills | §1 判断类型 | 事实进 memory，流程进 skill |

Hermes 默认「3+ 次」才自动创建技能；本技能保留这个门槛，但**用户明确要求**时可以提前固化。

## 4. 技能质量清单

创建 / 更新后逐项勾选：

- [ ] `name` 与目录名一致，小写短横线。
- [ ] `description` 含真实触发词，能让人一眼判断「什么时候用」。
- [ ] 触发 / 输入 / 输出 / 边界齐全。
- [ ] 每一步都有可验证的产出。
- [ ] 有判断规则，而不是只有顺风顺水的步骤。
- [ ] 有「坑与反例」，包含至少一个失败路径。
- [ ] 有验证方式与完成标准。
- [ ] 未复制其他技能 / 仓库长文，只引用。
- [ ] 脚本只读，或写操作显式可控。
- [ ] 已登记技能索引（本仓为 `agents/skills/README.md`）。
- [ ] `lint_skills.py` 为 0 ERROR。
- [ ] 至少真实试跑一次，记录了验证日期。

## 5. 合并 / 归档规则

- **合并**：两个技能触发器重叠超过一半，或步骤高度重合 → 合并到更具体、更常用的那个名字；旧名字在索引里标注「已合并 → 新技能」。
- **降级**：技能长期未使用、工具已废弃、被新技能替代 → 移入仓库的归档目录（如 `archive/<YYYYMM>/`），并在技能索引里标注去向。
- **不删除历史**：归档保留可追溯；技能文件本身是资产。
- **版本**：新建 `1.0.0`；小修 `+0.1`；结构调整 / 触发词变化 `+1.0`。
- **变更记录**：在 `SKILL.md` 末尾加一行 `- YYYY-MM-DD · vX.Y.Z · 改了什么 / 为什么`，最多保留最近 10 条。

## 6. 常见反模式

- 把「这次的任务记录」当成技能：里面全是专有名词和一次性数据。
- 写「所有 XX 流程」这种过宽技能：太长、太模糊，实际不会加载。
- 把事实 / 偏好写进技能：用户爱用深色模式、项目部署在哪个 IP，这些属于 memory。
- 只写成功路径，不写坑：下次遇到同样的坑还会踩。
- 每次使用都重写技能，没有版本、没有证据：无法判断是否真的进化。
- 未经用户确认就新建 / 改名 / 对外发布技能：违反所在仓库的发布规则。

## 7. 两个真实示例

**示例 A：内容归档 → 一个独立的内容技能**

- 观察：多次把收集的素材移到 `notes/` / `critiques/`，每次都涉及隐私门、命名、front-matter、索引同步。
- 判断：程序性知识、重复性高、有明确边界 → 固化。
- 产出：内容归档技能 + 路由表 + 只读体检脚本（作者本地配套，未随本仓发布）。
- 注意：它处理的是**内容**，不是工作流。

**示例 B：一次误解 → 技能进化**

- 观察：最初把「把工作流沉淀成技能」误解为「内容归档」，导致返工。
- 判断：这是**元流程**，跨任务复用，值得单独成技能。
- 产出：`skill-evolution` + 本文件 + lint 脚本；同时把内容归档拆成独立技能。
- 教训：先分清「整理内容」与「整理流程」，再决定写哪个技能。
