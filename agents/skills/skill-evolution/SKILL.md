# 技能进化（skill-evolution）

> **定位：元技能。** 它不直接做业务，而是把「刚做完的事」提炼成下次可复用的程序性知识。
> 本文件是公开可复用版本：不依赖作者的工作区，可放进任意 `skills/` 库。
> 参考 Hermes Agent 学习循环：**observe → distill → reuse → refine**；同一模式重复出现才固化，使用中按反馈修补。
> 与内容归档 / 素材整理技能分工：本技能整理**流程**，不整理**内容**。

---

## 1. 何时触发 / 不触发

**触发**

- 用户说「把这个流程沉淀成 skill」「把这套做法固化」「以后都这么做」。
- 一个复杂任务（≥5 步 / 多次工具调用）刚完成，且明显会重复 → Agent **主动提议**固化。
- 某个技能刚被使用，用户纠正了做法或踩到新坑 → 更新该技能。
- 周期性复盘：同一类工作已重复 2–3 次，值得从「每次临场做」升级为「按技能做」。

**不触发**

- 只做一次、以后不会重复的任务 → 记候选，不建技能。
- 纯事实 / 偏好（用户习惯、项目参数、环境信息）→ 写 memory / TODO / 项目文档，不是程序性知识。
- 已有技能能覆盖 → 更新已有技能，不新建。
- 内容归档 / 素材放哪 → 用对应的内容技能，不要用本技能。

---

## 2. 核心循环（四段）

| 阶段 | 做什么 | 产出 |
|---|---|---|
| **Observe 观察** | 回顾本次会话：步骤、工具、分支、纠正、踩坑、验证方式 | 证据清单 |
| **Distill 提炼** | 判断可复用性；提炼触发 / 输入 / 输出 / 边界 / 步骤 / 判断 / 坑 | `SKILL.md` 草稿 |
| **Reuse 复用** | 注册索引；下次按 `description` 匹配加载；用一个真实任务试跑 | 可加载的技能 |
| **Refine 精炼** | 使用中按反馈补坑、删冗余、改步骤；版本递增 | 新版本 |

---

## 3. 固化门槛（防止技能库变垃圾场）

满足**任一**才创建 / 更新：

1. 用户明确要求。
2. 同一模式已成功重复 **3 次以上**（Hermes 默认门槛）；至少 2 次且流程稳定。
3. 现有技能在使用中暴露缺口 / 被用户纠正。

否则：把候选写入你所在项目的 TODO / 候选清单，标注「已出现次数 / 下次观察点」，**不建空壳目录**。

---

## 4. 流程（七步）

### 0. 收集证据

按 [references/evolution.md](./references/evolution.md) §1 的证据模板，列出：

- 任务目标与起点。
- 实际步骤（按顺序）。
- 关键判断 / 分叉 / 为什么这么选。
- 失败路径、坑、用户纠正。
- 验证方式与最终结果。

只写**真实发生过的**，不补想象中的步骤；运行环境与工具版本要标注。跨会话证据可从项目记忆、TODO 与 git log 取。

### 1. 判断类型

- **程序性知识**（怎么做）→ 技能。
- **事实性知识**（是什么 / 用户偏好 / 项目参数）→ memory / TODO / 项目文档。
- **一次性内容** → 对应的内容归档 / 素材整理技能。
- **已有技能覆盖** → 直接走第 6 步「进化已有技能」。

### 2. 查重与定位

读 [skills/README.md](../README.md) 的技能索引；检查是否有同触发器、同输入输出、同步骤的技能。

- 有重叠 → 合并 / 扩展现有技能，**不新建**。
- 没有 → 新建 `skills/<name>/`。
- 一个技能只做一件事；名字用小写短横线，与 frontmatter 的 `name` 一致。

### 3. 提炼骨架

必须写清四件事：**触发词 / 输入 / 输出 / 边界（不能做什么）**。再写：

- 主流程（编号步骤，每步有产出）。
- 判断规则（分叉怎么选）。
- 坑与反例（失败路径、用户纠正、环境差异）。
- 验证（命令 / 检查点 / 完成标准）。

详细表格放 `references/`，`SKILL.md` 保持主流程；引用文件用相对链接。

### 4. 落盘

- 新建目录 + `SKILL.md`（frontmatter：`name` / `description` / `version`）。
- 需要时加 `references/` / `scripts/`；脚本默认**只读**，写操作必须显式说明且可控。
- 不复制已有技能的内容；不复述仓库 README / CONTEXT 的长段落，只引用。

### 5. 注册与验证

- 更新 [skills/README.md](../README.md) 的技能索引与分类。
- 视情况更新本仓 [README.md](../../../README.md) / [CONTEXT.md](../../../CONTEXT.md)。
- 在仓库根目录运行 `python agents/skills/skill-evolution/scripts/lint_skills.py`，**必须 0 ERROR**。
- 用一个真实任务试跑；在技能末尾记录「最后验证日期」。

### 6. 进化已有技能（Refine）

技能被使用后出现以下信号，**直接改技能**，而不是只改这一次的输出：

- 用户纠正了步骤 / 口径。
- 踩到技能未覆盖的坑。
- 某步骤反复被跳过或证明无效。
- 工具 / 环境 / 约定变化。

动作顺序：补「坑与反例」→ 调整步骤 → 更新验证 → 版本 `+0.1`（结构性变化 `+1.0`）→ 在技能末尾记一行变更记录。
**失败路径要剪枝**：不再有效的步骤删掉，不要越积越长。

### 7. 回报

1. **新建 / 更新了哪个技能**，证据是什么。
2. **验证结果**：lint + 真实试跑结论。
3. **未决**：哪些只是候选、哪些需要人工确认（对外发布 / 删除 / 改名）。

---

## 5. 质量红线

- 技能是**程序性记忆**，不是日记：不写「这次做了什么」，只写「下次怎么做」。
- 不把一次性任务包装成通用技能；不写「所有 XX」这种过宽技能。
- 不写未验证的步骤；不确定的地方标「待验证」。
- 不写密钥、隐私、用户数据；不写本机绝对路径与真实姓名（见 [agents/README.md](../../README.md) 的脱敏红线）。
- 技能更新不改用户观点、不编造事实。
- 公开仓 push / 删除 / 改名仍需人工确认。
