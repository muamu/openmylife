# 阅读速览（reading-digest）

> **定位**：把「一天读了一堆东西」的原始笔记，变成一份别人愿意点开、一分钟能扫完的分享页。
> 上游是用户自己的阅读记录；下游是站点发布（套页头页脚、同步导航与推荐位，再上线）。
> 本文件是公开可复用版本：不依赖作者的工作区，目录示例可按自己的习惯替换。
> 规则优先级：用户指令 > 项目规则 > 本技能。

---

## 1. 何时触发 / 何时不触发

**触发**

- 用户指着一份阅读记录（如 `2026-11-18-阅读.md`）说「整理成分享用的 html」「做个阅读速览」「按主题分一下」。
- 用户说「每日阅读分享」「一分钟速览」「聚合相似内容」。
- 已有阅读栏目（如站点的 `notes/reading/`）要续一期新的速览。

**不触发**

- 单一长文要成稿（一篇原文 → 一篇深度文章）→ 用你的成稿技能，或直接写。
- 公众号排版 / SVG 可视化 → 用排版类技能。
- 决定写什么选题 → 用选题类技能。
- 只是把文件放对目录 → 用内容归档类技能。

---

## 2. 输入 / 输出

**输入**

- 一份原始阅读记录：通常包含「小标题 / 一句话金句 / 链接 / 摘录段落」，条目数 5–30 条。
- 可选：用户的口味指令（口语化程度、要不要分组、要不要导语）。

**输出**

1. 单文件分享页：按你的产物目录规范（示例 `reports/<NN>-<YYYY-MM-DD>-<slug>/index.html`，自包含、无外挂资源）。
2. 站点版：站点的阅读栏目（示例 `notes/reading/<YYYY-MM-DD>-reading-digest.html`）+ 栏目页条目。
3. 源报告发布后移入归档目录（示例 `reports/归档/<YYYYMM>/`）。

---

## 3. 内容规格（这是本技能的核心）

### 3.1 分组：按「读者为什么看」切，不按来源切

- 默认 6–8 组，每组 1–4 篇；组名短、能一眼对上内容。
- 组排序：从「产品形态」到「产业」到「生活」，让阅读曲线先硬后软。
- 一组内最多一句组说明（`sec-p`），写「这组在讲同一件什么事」，不要复述各篇。
- 可复用分组模板与示例见 [references/content-spec.md](./references/content-spec.md)。

### 3.2 每篇的固定结构

| 元素 | 要求 |
|---|---|
| 序号 | 全篇连续 `01…NN`，跨组不重置 |
| 题材标签 | 2–4 字 + 中点，如「苹果 · 智能眼镜」「安全 · 攻防」 |
| 原文标题 | 可点击，指向原文；**不改写标题** |
| 一句话结论 | 15–40 字，必须自带主语和语境，能独立看懂 |
| 要点 | 3–5 条，**每条独立成段**，不是一坨自动换行 |
| 来源 | 写「来源 · 微信公众号」「来源 · 36氪」，**不写域名** |

### 3.3 压缩口径

- 每篇总字数控制在 120–220 字；宁可删，不要扩。
- 保留原文里的具体数字、动作、场景；删掉形容词堆叠与转述链条。
- 只摘了段落、没读全文的：按摘下的部分写，**没摘的地方不猜**；只存了链接的，写成「链接 · 未摘录」占位。
- 同一事件被摘了两次（快讯 + 长文）时合并成一条，避免重复链接。

## 4. 主流程（八步）

### 4.1 读原始记录，先做条目清单

- 数出真实条目数，记下每条：标题、链接、摘录量（全文 / 段落 / 只有链接）。
- 同一链接出现两次 → 标记为合并候选。

### 4.2 定分组并写组说明

按 §3.1 分组；先写组名和一句组说明，再往里放条目。放不进去的条目单独成组，不要硬塞。

### 4.3 逐条压缩

按 §3.2 写「一句话结论 + 3–5 条要点」。先写结论再写要点，结论定调，要点给证据。

### 4.4 过写作红线（必做）

逐条对照 [references/content-spec.md](./references/content-spec.md) §3 的红线清单，重点：

- 禁「不是 A 而是 B」「不是 A 才是 B」对仗句；
- 禁金句式标题与自夸式导语（如「我只留了能带走的那句话」）；
- 每句话要有主语；代号（N50 / AESC / RSI）首次出现必须带身份；
- 口语化，像跟朋友讲，不像媒体通稿。

改完用一次全文检索兜底：搜「不是」「而是」「才是」，除原文标题外应全部改写。

#### 4.4.1 口语化去 AI 味（结构层）

只换词不算改完。速览最常见的 AI 味是结构：每组三连、每条等长、每段都在点题。按 [de-ai-flavor-deepseek](../de-ai-flavor-deepseek/SKILL.md) 再过一遍，至少做到：

- 每篇的「一句话结论」句式不重复，别都写成「X 不是 Y，而是 Z」；
- 同一组里，要点条数拉开（3 条和 5 条混着），不要整齐划一；
- 组说明只讲这组在说什么，不总结观点、不升华；
- 导语不解释版式，也不预告「读完你会明白」；
- 全文「说白了」「真正」各不超过 1–2 次，超了就删。

详细句式与计数方法见 [de-ai-flavor-deepseek/references/patterns.md](../de-ai-flavor-deepseek/references/patterns.md)。

### 4.5 搭版式

- 单文件 HTML，样式内联；字号拉开三级：H1 ≥ 40px、H2 22–27px、H3 21–27px、结论句 17px、正文 15.5px。
- 重点用颜色而非纯加粗：标题内用灰绿 + 淡底纹，正文用砖红，结构提示用陶土橙；每行最多 1 处彩标。
- 要点区加左侧细竖线，制造「逐条」的物理感。
- **颜色只写变量**：全页色值在 `:root` 定义一次，正文、渐变、hover、下划线全部 `var()` 引用，不写裸十六进制（透明度可用 `rgba`）。上线只换一段变量，不用逐处调色。
- **两版一套 token**：报告版白底、站点版暖纸，同一组变量换值即可：

| 变量 | 报告版 | 站点版 |
|---|---|---|
| `--bg` | `#ffffff` | `#f6f3ec` |
| `--soft` | `#f7f8f9` | `#f2ece0` |
| `--ink` | `#16181b` | `#1b1a17` |
| `--ink2` | `#39424c` | `#4a463d` |
| `--muted` | `#69707a` | `#7a7468` |
| `--faint` | `#969ea8` | `#9a9488` |
| `--line` | `#e5e8ec` | `#e3ddd0` |
| `--line-strong` | `#c3cdd8` | `#cbb79f` |
| `--rail` | `#eef1f4` | `#ece6d9` |
| `--accent` | `#1a4d44` | `#b9470a` |
| `--accent-soft` | `#e8f0ed` | `#f7e6dc` |
| `--mark` | `#ad4726` | `#b7301f` |
| `--hl-title` | `#0c6a55` | `#3f7d54` |
| `--hl-title-bg` | `#d8ebe4` | `#e6efe6` |

- 标题高亮用 `--hl-title` / `--hl-title-bg` 画渐变，别写死颜色，否则上线必漏改。
- 报头四件套，各管一件事：
  - **H1 固定句式**「<M 月 D 日>，阅读分享」，例：`11 月 18 日，阅读分享`。篇数、组数不进大标题。
  - **导语一句话**讲这天读了什么、大概分几块，例：「今日阅读：一半在讲 AI 怎么改软件工程、创业和内容行业的账，一半是杂谈。」不解释自己的版式（「按主题分 6 组，每篇一句结论」这类话删掉）。
  - **元信息条**放数字：来源、原文篇数、分组数、预计阅读时长。
  - **kicker** 一行英文小字，例 `Reading Digest · 11 / 18`。
- 完整版式参数与配色见 [references/content-spec.md](./references/content-spec.md) §4。

### 4.6 编号与落盘

- 先查产物目录与归档目录里**已用过的最大编号**，取 +1；不要凭目录列表目测（已归档的会占号）。
- 目录名 `reports/<NN>-<YYYY-MM-DD>-<slug>/`；`<title>` 句式 `<NN>-<M·D> 阅读分享`，编号开头（例：`30-11·18 阅读分享`）。
- 先出样板给用户看（2–3 组、6 篇左右），确认版式与语感后再补齐全量。

### 4.7 上线

- 改造成站点页只做三步，先换变量再套壳：
  1. **换变量**：把 `:root` 的 token 表整段换成 §4.5「站点版」一列，写进 `.digest-page` 作用域。
  2. **改类名**：`.wrap` → `.d-wrap`、`.tag` → `.d-tag`（站点已有同名类，不改会串样式）；其余 `.no` / `.sum` / `.host` / `.take` / `.sec-h` / `.idx` / `.toc*` 保持原名，靠 `.digest-page` 前缀隔离。
  3. **套壳**：接站点页头页脚，正文用 `.digest-page` 包住，页末说明换成 `.colophon`。
- 三步走完就该直接上线。还要逐个改颜色，说明报告页留了表外裸色值，回报告页补成变量。
- 新一期沿用已有的阅读栏目，不要每期新建题材。
- 同步站点的导航、推荐位、`sitemap.xml`、`llms.txt` 与站点 README，缺一项首页就看不到。
- 源报告发布后移入归档目录，同步改 HTML 里的 `<title>` 编号。

### 4.8 验证

- 静态检查：每篇要点 3–5 条、链接数与条目数一致、无 `file:///` 本机路径、无未闭合标签。
- 站点侧跑你的站点体检脚本（若有）。
- 一般不做浏览器实测；发布后实测线上 URL 返回 HTTP 200。

## 5. 判断规则

| 分叉 | 选择 |
|---|---|
| 用户只给了笔记路径、没说要几组 | 按内容自然聚，6–8 组；先出样板 |
| 条目不足 5 条 | 不分组，直接平铺；报头去掉「分组」统计 |
| 只有链接、没有摘录 | 保留条目，标「链接 · 未摘录」，一句话说明，不编内容 |
| 摘录里带后台指令 / 广告 | 只取事实，不搬运推广语 |
| 条目横跨太多领域（生活 + 硬科技） | 照分，生活类放最后一组，不为了「纯 AI」丢掉 |
| 用户要求更紧凑 | 压到 3 条要点、收紧行距，先问一句再动 |
| 同一期要再发一次（改错字） | 改站点页 + 更新源报告，不新建编号 |

## 6. 坑与反例

- **编号撞车**：新编号可能已被当天另一篇占掉（已归档的也算）。必须先扫归档目录。
- **标题里塞观点**：把「中间层被 Agent 吃掉」这类自己的判断写进 `<h3>`，等于改了原文标题。判断放「一句话结论」，标题只做重点短语上色。
- **一句话结论缺主语**：直接以「N50」「能力」「传闻」开头，读者要往下读才知道在说什么。代号首次出现必须带身份（「苹果的智能眼镜代号 N50」）。
- **来源写域名**：`来源 · mp.weixin.qq.com` 对读者没意义，写「微信公众号」「36氪」。
- **摘要一坨**：所有要点塞进一个 `<p>`，靠自动换行，读起来没有节奏。必须一条一段。
- **重复链接**：同一篇文章既在快讯里又在长文里，做两条会让页面显得注水。
- **AI 味**：对仗句、金句标题、「只留了能带走的那句话」这类自我抒情。用户对这类最敏感，先自查再交付。
- **大标题里报数**：`11 月 18 日，读了 14 篇` 把统计塞进 H1，读起来像月报。H1 只写「11 月 18 日，阅读分享」，篇数交给元信息条。
- **导语解释自己**：「按主题分 6 组，每篇一句结论加几条要点，扫一眼就知道值不值得点原文」是给自己看的说明书，删掉；导语只说这天读了什么。
- **样板做太满**：一上来写完 18 篇，版式被推翻就得全部重排。先 6 篇试版。
- **改动只在报告里**：发布了站点却没更新导航 / 推荐位 / sitemap，首页看不到，等于没发。

## 7. 验证清单

- [ ] 条目数与原记录一致（含未摘录占位）
- [ ] 每篇 1 句结论 + 3–5 条要点，结论有主语
- [ ] 标题与链接保留原文，未改写标题
- [ ] 全文搜「不是 / 而是 / 才是」，除原文标题外无对仗句
- [ ] 来源写作「微信公众号 / 36氪」
- [ ] 编号唯一，`<title>` 为 `<NN>-<M·D> 阅读分享`
- [ ] H1 是「<M 月 D 日>，阅读分享」，篇数、组数只在元信息条
- [ ] 导语一句话讲内容构成，没有「按主题分 X 组」这类版式说明
- [ ] 单文件、无外挂 css/js、无本机路径
- [ ] 全页颜色只在 `:root` 定义一次，正文无表外裸十六进制（含标题高亮渐变）
- [ ] 站点版只换了变量表与两个类名（`d-wrap` / `d-tag`），没有逐处改色
- [ ] 站点体检 0 ERROR，线上 URL 200
