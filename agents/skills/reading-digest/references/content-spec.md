> 只在需要对齐口径时读，不必每次全文加载。

## 1. 分组模板

按「读者为什么要看」切，默认从硬到软。组数 6–8，每组 1–4 篇。

| 序 | 组名 | 收什么 |
|---|---|---|
| 01 | 硬件与产品形态 | 新硬件、新形态、消费级 Agent 的体验边界 |
| 02 | 软件工程与开发者 | 写代码这件事怎么变、工程流程怎么变 |
| 03 | AI 与专业能力 | AI 与人协作、专业判断被侵蚀或放大 |
| 04 | AGI 路线与模型能力 | 访谈、对谈、能力边界、产品快讯 |
| 05 | 算力基建与产业 | 数据中心、供应链、公司估值、上下游生意 |
| 06 | 投资与安全 | 资金流向、攻防、风险 |
| 07 | 生活与健康 | 与工作无关但用得上的 |

**组说明写法**

- 一句话，讲「这组在讲同一件什么事」，不是复述每篇。
- 好：「一组是苹果的眼镜，一组是 a16z 的消费 Agent。说的是同一件事：硬件越来越像壳，决定成败的是里面那个 AI。」
- 差：「本组包含两篇文章，分别讨论了苹果和 a16z……」（目录腔）

**条目少于一组的量**：1 篇也可以成组，但组说明要写清它为什么单独成组；否则并到相邻组。

## 2. 压缩示例（原文摘录 → 速览）

### 示例 A：长文 → 一句结论 + 4 条

原文（约 900 字摘录，含代号、时间表、架构、生态、范式判断）

产出：

> **一句话结论**：苹果的智能眼镜代号 N50，干脆不要屏幕，成败全看 Siri 什么时候补完课。
>
> 1. 内部代号 N50，砍掉光波导屏幕，用老款 Apple Watch 那颗芯片的架构，配精简版 visionOS，做出来是一副很普通的眼镜，内部叫它「戴在脸上的 AirPods」。
> 2. 时间表压在 2027 年 6 月 WWDC 亮相、年底发货。卡住的地方在 Siri，硬件其实早就定型了。
> 3. 它不能自己跑第三方 App，靠 iOS 27.3 起的新 Siri 用语音调用 iPhone 上的应用，开发者不用单独开发，改改现有 App 就能接。
> 4. 文章真正想说的是：以前硬件开荒、软件在划好的圈里长，这次换过来了，硬件退到后面当安静的采集器，胜负交给软件。

要点：**保留数字与专有名词，删掉推演与形容词**；结论自带身份（苹果的智能眼镜），不靠代号开头。

### 示例 B：只剩段落 → 三条

原文只有三五段零散摘录时：第一条交代背景，第二条给冲突或机制，第三条给结论或边界。不要为了凑条数编内容。

### 示例 C：只有链接

> **标签**：链接 · 未摘录
> **结论**：这篇当天只存了链接，没来得及摘。
> **要点**：先占个位置，等回头补上再写。

## 3. 写作红线

### 3.1 禁句式

| 禁用 | 为什么 | 改成 |
|---|---|---|
| 「不是 A，而是 B」/「不是 A，是 B」 | 对仗腔，读起来像通稿 | 直接陈述 B，或写成因果 |
| 「不是 A，才是 B」 | 同上，且带说教感 | 「问题出在 B」 |
| 「从 X 到 Y」的对仗副标题 | 空心结构 | 写具体动作或数字 |
| 金句式主标题（「我只留了能带走的那句话」） | 自我抒情，AI 味重 | 固定句式：「11 月 18 日，阅读分享」 |
| 统计式主标题（「11 月 18 日，读了 14 篇」） | 像月报，读者不关心篇数 | 篇数挪进元信息条，H1 只留日期 + 阅读分享 |
| 「真正想说的是」「本质上」高频复用 | 空转 | 直接给结论 |
| 三段排比 + 破折号总结 | 模板感 | 拆成两句 |

原文标题里本来就有的对仗句，保留，不算违规。

### 3.2 必须做到

- **每句有主语**：代号（N50 / AESC / RSI）、代词（他 / 它）、半截话题（「传闻里要 IPO 的……」）首次出现都要交代身份。
- **来源写介质**：「微信公众号」「36氪」，不写 `mp.weixin.qq.com`、`m.36kr.com`。
- **标题不改写**：原文标题原样保留；要补语境就补在「一句话结论」里。
- **口语但不油**：像跟朋友讲这件事，允许「说白了」「这事」「挺」，不用网络热梗与感叹号堆叠。
- **数字照抄**：原文的金额、日期、比例不四舍五入，也不补算。

### 3.3 自查命令

全文检索以下词，除原文标题外应为 0：

```
不是 / 而是 / 才是 / 本质上 / 真正想说的是 / 只留了
```

## 4. 版式参数

### 4.1 字号层级

| 元素 | 字号 | 说明 |
|---|---|---|
| H1 | `clamp(30px, 8.4vw, 46px)` | 固定句式「<M 月 D 日>，阅读分享」，不写篇数、不用金句 |
| 组标题 H2 | 22px（≥700px 时 26–27px） | 配一个编号徽章 |
| 文章标题 H3 | `clamp(21px, 5.4vw, 27px)` | 可点击，行高 1.36–1.4 |
| 一句话结论 | 17px / 700 | 单独成段，与正文拉开 |
| 要点正文 | 15.5px / 1.75 | 每条独立 `<p>` |
| 元信息、来源 | 11.5–12.5px | 灰 |

### 4.2 配色：两版一套 token

颜色只在 `:root` 定义一次，正文、渐变、hover、下划线全部 `var()` 引用；页面里不出现表外的裸十六进制（透明度用 `rgba`）。报告版与站点版共用变量名，上线只换一列值。

| 变量 | 用途 | 报告版 | 站点版 |
|---|---|---|---|
| `--bg` | 纸面 | `#ffffff` | `#f6f3ec` |
| `--soft` | 浅底 / code 背景 | `#f7f8f9` | `#f2ece0` |
| `--ink` | 正文字色 | `#16181b` | `#1b1a17` |
| `--ink2` | 次级正文 | `#39424c` | `#4a463d` |
| `--muted` | 组说明 / 元信息 | `#69707a` | `#7a7468` |
| `--faint` | 序号 / 来源 | `#969ea8` | `#9a9488` |
| `--line` | 分割线 | `#e5e8ec` | `#e3ddd0` |
| `--line-strong` | hover 描边 | `#c3cdd8` | `#cbb79f` |
| `--rail` | 要点区竖线 | `#eef1f4` | `#ece6d9` |
| `--accent` | 结论句 / 组徽章 | `#1a4d44` | `#b9470a` |
| `--accent-soft` | 徽章底色 | `#e8f0ed` | `#f7e6dc` |
| `--mark` | 正文重点 | `#ad4726` | `#b7301f` |
| `--hl-title` | 标题内重点字 | `#0c6a55` | `#3f7d54` |
| `--hl-title-bg` | 标题重点底纹 | `#d8ebe4` | `#e6efe6` |

报告版变量块（直接复制，站点版只替换值并加 `.digest-page` 前缀）：

```css
:root{
  --ink:#16181b; --ink2:#39424c; --muted:#69707a; --faint:#969ea8;
  --line:#e5e8ec; --line-strong:#c3cdd8; --rail:#eef1f4;
  --bg:#ffffff; --soft:#f7f8f9;
  --accent:#1a4d44; --accent-soft:#e8f0ed;
  --mark:#ad4726;
  --hl-title:#0c6a55; --hl-title-bg:#d8ebe4;
}
```

标题高亮写成 `color:var(--hl-title);background:linear-gradient(180deg,transparent 60%,var(--hl-title-bg) 60%)`，不要在渐变里写死颜色。

规则：**用颜色做重点，不靠加粗堆叠**；每行最多 1 处彩标；标题里的重点短语加淡底纹（马克笔效果），否则深色字在深色标题里看不出差别。

### 4.3 结构参数

- 要点区：`border-left:2px solid` 细竖线 + 左内边距 15–18px。
- 条目之间：`border-top:1px solid`，上内边距 26px，下 28px。
- 组之间：上外边距 44–52px。
- 目录：两列网格（≥620px），每行「编号 组名 + 篇数」。
- 报头：kicker（英文小字，如 `Reading Digest · 11 / 18`）+ H1（`11 月 18 日，阅读分享`）+ 导语一句话（讲内容构成，不解释版式）+ 元信息条（来源 / 篇数 / 组数 / 阅读时长）。

### 4.4 文件约束

- 单文件，样式与脚本内联；不引外链字体、不生成 `assets/` 旁挂目录。
- 站点版套站点页头页脚，样式全部限定在 `.digest-page` 内；`.wrap`、`.tag` 这类站点已使用的类名要改名（如 `d-wrap`、`d-tag`）。
- 页面内不出现本机绝对路径。

## 5. 发布衔接

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 接入站点 | 套站点页头页脚、把样式限定在 `.digest-page` | 复用已有阅读栏目，不要把每期做成新题材 |
| 导航与推荐位 | 在站点导航、首页推荐、栏目页加条目 | 只发页面不改这些，首页看不到，等于没发 |
| 上线 | 上传站点文件 | 逐个上传改动文件即可；排除模板与 README 这类非站点文件 |
| 归档 | 源报告移入归档目录 | 同步改 `<title>` 编号 |
