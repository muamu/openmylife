# 口语化去 AI 味 · DeepSeek 版（de-ai-flavor-deepseek）

> **定位**：稿子已经有材料、有判断，但读起来像通稿或模型产物。这个技能只做一件事——把表达改回一个人说话的样子。
> **不负责**：从零写稿、找材料、排版、发布。上游可以是任何成稿（洞察、清单、阅读速览、公众号、报告），改完交回原流程。
> **模型口径**：本版基于 DeepSeek-V4.1-Flash 的生成特征整理。不同模型的「AI 味」不完全一样，后续按模型分目录维护，见 §0。
> 本文件是公开可复用版本：不依赖作者的工作区，可放进任意 `skills/` 库。
> 规则优先级：用户指令 > 项目规则 > 本技能。

## 0. 版本与命名（多模型并存）

技能按「动作 + 模型」命名，避免不同模型的改法混在一份清单里：

```
skills/
├── de-ai-flavor-deepseek/   ← 本版
├── de-ai-flavor-claude/     ← 以后按需新增
└── de-ai-flavor-gpt/        ← 以后按需新增
```

**新增一个模型版本时**

1. 复制本目录，改 `name` 与目录名（`de-ai-flavor-<model>`）。
2. 只改三处：§1 的模型特征、§5 的阈值、§6 的案例；§3 的四遍改法保持通用。
3. 在技能索引 `skills/README.md` 的同一行系里新增一条，写清「哪个模型用哪版」。
4. 通用清单累计到 3 个模型版本后，再把公共部分抽到共享 reference，避免各抄一份。

**本版观察到的 DeepSeek 特征**（每次遇到新特征就往这里补）

- 小标题爱用工整对仗：「通道 / 通行证 / 记忆」这类三件套，且全文反复当骨架。
- 段落收尾爱补一句短句金句，形成「事实 + 点题」的固定节奏。
- 连接词偏多：「不是……而是……」「真正……的是」「更关键的是」。
- 口语化时容易只替换词，不动结构；`说白了` 会越用越多，变成新的模板。

## 1. 何时触发 / 何时不触发

**触发**

- 用户说「去 AI 味」「AI 味太重」「口语化重写」「读起来像 AI」「改得像人写的」。
- 自查时发现成段对仗、每节结构一样、结尾都在升华。
- 同一篇稿子被用户指出「太顺了」「像通稿」「没有你自己的判断」。

**不触发**

- 还没有事实与结构，需要从零写 → 先用你惯用的成稿技能或流程。
- 只改错别字、标点、格式 → 直接改，不必套流程。
- 公众号排版、SVG 可视化 → 交给排版类技能。
- 合同、公告、法律文本 → 不口语化，只做事实核对。

## 2. 先判断：AI 味在哪一层

AI 味不是一个词的问题，从轻到重分四层。**先看最重的两层，别在词上打转。**

| 层 | 症状 | 改起来的成本 |
|---|---|---|
| **材料** | 没有具体数字、时间、人名、失败细节；全是「显著提升」「大幅降低」 | 要补事实，最贵 |
| **结构** | 每段等长、每节同构、段末必点题、结尾升华、三连排比、自造分类贯穿全文 | 中，但最见效 |
| **句子** | 句长均匀、没有停顿和插话、每句都完整、连接词密集（更关键的是、值得注意的是、换句话说） | 低 |
| **词** | 破折号、引号包概念、「真正 / 本质 / 核心 / 赋能」高频 | 最低，但单独改没用 |

两条原则：

1. **频率不是罪名。**「不是 A 而是 B」本身没错，一篇出现两次和出现十二次是两件事。先数频率，再决定动不动。
2. **先删，再改。** 一句没有信息量的话，改十遍还是废话。删掉之后，剩下的句子往往自己就顺了。

## 3. 四遍改法

### P0 删：先问「这句有没有东西」

- 把每段压成一句「这段在说什么」。说不出来的，整段删。
- 删掉所有「总结上一段」和「预告下一段」的句子。
- 删掉形容词堆叠：把「极其重要且极具潜力」换成具体后果。

### P1 结构：拆对称（最见效）

- **拆段末点题**：一段结束时不再补一句金句；让事实自己停住。
- **拆三连**：三个并列改两个或四个，且长度不一样；不要「既能 A，又能 B，还能 C」。
- **拆同构**：不是每节都要「现象—原因—结论」。有的节可以只讲一个案例，有的节可以直接给数。
- **拆抽屉名**：自己起的分类（「三张执照」「四层地图」）第一次出现前，先把事讲清楚；全文不超过两次，别拿它当小标题模板。
- **补判断过程**：加一句「我一开始以为……后来发现不对」，比十句结论更像人。
- **允许不解决**：留一句「这条我没查到」「现在还没有答案」，比强行收束可信。

### P2 句子：把节奏打乱

- 长短句交替。连续三句长度差不多，就砍一句或拆一句。
- 允许口语插入：「说白了」「这事有点怪」「我换个说法」——但**一篇最多一两次**，多了就是新的模板。
- 少用连接词开头。把「更关键的是」直接删掉，读者接得上。
- 把「这意味着」「换句话说」换成直接说结果。
- 数字和口径保留原样，不许为了顺口改掉。

### P3 材料：每个判断配一个可核对的东西

- 每 500 字至少有一个具体数字、时间、人名、产品名或可查的事件。
- 关键数字带口径：谁说的、什么时点、分母是什么。
- 有反例就写反例；有矛盾就写矛盾，不要抹平。

### P4 朗读与计数

- 出声读一遍。读着要换气的地方，就是句子太长；读着别扭的地方，多半是书面语没换掉。
- 用 [references/patterns.md](./references/patterns.md) 的可数清单扫一遍，超标的才改，不是见一个杀一个。

## 4. 结构自查（六条，命中三条以上就要动）

- [ ] 每段结尾都在点题或升华
- [ ] 全文有三处以上「三连」结构（三列、三张卡、三个词）
- [ ] 各节长度和内部结构高度一致
- [ ] 自造概念（XX 三层、XX 四张牌）反复出现，成了小标题
- [ ] 每段都在重复同一个论点，没有新事实
- [ ] 把作者名字换成任何人，句子照样成立

## 5. 可数清单（检查线索，不是禁令）

| 项 | 建议上限 | 说明 |
|---|---|---|
| 「不是……而是……」 | ≤ 2 次 / 千字 | 超出就挑最没信息量的两句改掉 |
| 「说白了 / 说白了就是」 | 0–1 次 / 篇 | 用多了是新的 AI 口头禅 |
| 「真正 / 本质 / 核心是」 | ≤ 3 次 / 篇 | 多为空转，删了不影响意思 |
| 段末单句成段（金句位） | ≤ 2 次 / 篇 | 其余并回上一段 |
| 三连排比 | ≤ 3 次 / 篇 | 包含「三列卡片」「三个分点」这类版式 |
| 连续三句句长差 | < 10% 就改 | 节奏过匀是明显机器特征 |
| 破折号 | 看密度，不设零容忍 | 中文里本来就有正经用法 |
| 每 500 字可核对细节 | ≥ 1 个 | 数字、时间、人名、事件都算 |

阈值只是红灯：灯亮了看一眼，不是掉头。

## 6. 真实案例（2026-11 《个人助理 V5 洞察》改稿）

| 改前 | 改后 |
|---|---|
| 标题「代理权的三张执照」 | 「AI 想替你出门，得先有人给它开门」 |
| 「这个月最值钱的两条新闻，都不在『产品』上」 | 「先说两笔钱。一笔 9000 万美元，一笔 450 万」 |
| 每节固定「事实 → 金句收束」 | 有的段落在事实上停住，有的直接拐进下一件事 |
| 结尾四连排比「有人在修路，有人在发通行证……」 | 「Linq 和 Photon 在修路，Poppy 在写门规，Second 在保管记忆。至于最后谁靠这个挣钱，账单还没出来。」 |
| 「说白了」×4、「真正」×6 | 0 和 2 |

同一次改动里，数字、融资额、来源、口径全部未动。

## 7. 与其它技能的关系

- 阅读速览类技能：速览写完后用它过一遍口语层，见 [reading-digest](../reading-digest/SKILL.md)。

- 站点接入与部署：只做发布，不要在这一步改文案；上线前不再改稿。

## 8. 边界（不能做什么）

- **不虚构**：不加没发生过的个人经历、对话、现场细节。
- **不改数**：数字、日期、口径、引语原样保留；改不动就标注存疑。
- **不改立场**：可以把话说直，不能把作者的观点改反。
- **不万能口语化**：公告、合同、法律、财报原文不适用。
- **不一次改到底**：先出 1–2 节样板给用户确认语感，再全量改。
